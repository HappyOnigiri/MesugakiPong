# リポジトリ基本ルール

このリポジトリは「MesugakiPong」の単体アプリケーションです。

## 1. Git 操作の制限

- **自動コミットの禁止**: ユーザーから明示的な指示がない限り、`git commit` や `git push` を自動実行しないでください。
- コミットを行う際は、`commit` スキルを推奨します。

## 2. CI と品質保証

- **検証の必須化**: コード変更後は必ず `make ci` を実行し、全チェックが成功することを確認してください（`any` 型や `@ts-ignore` は原則禁止です）。
- プロジェクト全体を俯瞰したい場合は、`make repomix` でコンテキスト生成を行ってください。

## 3. Architecture Map の運用

- `architecture-map.md` には、AIエージェントがコマンドですぐ調査できる自明な事実（ディレクトリツリーなど）は**書かない**でください。
- 代わりに、「特定モジュール間の暗黙的な依存関係」「調査コストが高い歴史的経緯」「一見して直感的でない設計意図（勘違いしやすい点）」など、高コンテキストな情報のみを記載してコンパクトに維持してください。
- 新しい作業を始める前にこれを読み、重要な設計変更を行った場合は実態に合わせて更新してください。

## 4. 言語ルール（最優先）

- すべての回答、思考プロセス、アーティファクト、コード内のコメントは、例外なく**厳密な日本語**で記述してください。

## 5. 意図コメント

以下のような意図的な実装（非効率やバグに見えるもの）には指定のタグコメントを付与し、原則として変更・削除してはいけません：
- `[Intended] 理由` — 仕様・設計上の意図
- `[Policy] 理由` — 運用ルール・組織方針
- `[Workaround] 理由` — 外部バグ回避策等
